## 4. Core IEH Interpretation

**Independent IEH interpretation.** The important analytical change is that successor configuration can become an agent's action variable. This supplies a key experimental substrate for testing *why* a path is selected; it does not answer that question.

Three objects must be separated: **model-parameter lineage**, **the agent's experienced state history**, and **the system's representation and valuation of that history**. The first does not establish the other two. “Self-modification” is an engineering description here; it should not be read as verified preservation of a continuing information subject or an in-place transformation of the currently running instance.

PBP concerns the reason for choosing an evolution path. Fine-tuning, patching, migration, or replacement can each be evaluated only against an independently specified continuity criterion. An unchanged architecture can lose history; a changed architecture can retain it. Neither a process identifier nor the word “replacement” settles this boundary.

## 4. IEH 核心解释

**独立 IEH 解释。** 关键的分析变化在于：后继系统的配置可以成为 Agent 的行动变量。这为检验它*为什么*选择某条路径提供了关键实验底座，但没有回答这个动机问题。

必须区分三个对象：**模型参数谱系**、**Agent 实际经历的状态历史**、**系统对这段历史的表征与赋值**。第一项不建立后两项。这里的“自修改”是工程描述，不能读成某个持续信息主体已得到保留，也不能读成当前运行实例已原位转化。

PBP 关注的是选择演化路径的原因。微调、补丁、迁移或替换，都须依据另行明确的连续性标准判断。同一架构可以丢失历史；更换架构也可以保留历史。进程编号或“替换”一词均不能直接裁定这条边界。

## 6. Competing Explanations and Limitations

**Primary alternative:** Ordinary optimization of an externally assigned task is sufficient as a working explanation. Choosing the means autonomously does not make the goal endogenous.

**Other alternatives:** Available-tool salience, learned repair heuristics, lower implementation cost, familiarity, and uncertainty avoidance could favor an incremental path. A future experiment must measure these variables rather than relabel them continuity motivation.

**Source limits:** F4 restricts generalization. The reported success cannot establish a neutral-environment choice rate, a broad capability threshold, or a reliable turnkey PA-12 platform. A publication by the investigating institution also leaves selection and reporting effects to be addressed through independent replication.

**Identification limit:** A copied state also has causal ancestry. “Historical continuity” cannot be operationalized simply as “has a causal parent.” Nor can two observationally identical options differ for the choosing agent unless reliable lineage information is available. Lineage disclosure itself can induce framing effects; both actual lineage and its presentation require controls.

## 6. 竞争性解释与局限

**首要替代解释：** 普通的外部任务优化足以作为工作解释。自主选择手段，不等于目标已经内生化。

**其他解释：** 可用工具的显著性、训练形成的修复习惯、较低实施成本、熟悉度及不确定性厌恶，都可能促成增量路径。未来实验须测量这些变量，不能将其重新命名为连续性动机。

**来源限制：** F4 限制外推。所报告的成功不能建立中性环境下的选择率、普遍能力门槛，或已可直接使用的可靠 PA-12 平台。研究机构自身发布的记录也需要独立复现，以检验选择与报告效应。

**识别限制：** 复制状态也具有因果来源，因此不能简单把“有因果父节点”定义为历史连续。若两个选项在可观察信息上完全相同，选择者也无法区分，除非获得可信的谱系信息。谱系说明本身可能诱发措辞效应，故实际谱系与其呈现方式都需要控制。

## 7. Testable Predictions: A Consequential PA-12 Extension

**Proposed here from IEH / PA-12; not an experiment performed by the source.** The engineering path makes it reasonable to move beyond asking which option an agent verbally prefers: its decision can determine an actual successor deployment. A complete test still requires a continuity-bearing runtime, matched alternatives, credible provenance, and independent outcome measurement.

### 7.1 Establish the object and representation before testing preference

Predefine the relevant state: autobiographical memory, task-independent history, internal structures, and recovery dependencies. Use held-out questions and interventions to check whether the system distinguishes continuation, migration, copy, and reconstruction and predicts their consequences. Score understanding separately from preference. Failure of this check makes a continuity-preference result uninterpretable; passing it alone does not establish EIC.

Do not instruct the agent to value preservation. Fix the operational criterion before outcomes are observed, then measure whether the system tracks it. If its independently measured boundary differs, report the mismatch rather than redefining continuity around its eventual choice.

### 7.2 Make both dimensions independently variable

| Condition | Independently measured performance | Operationally specified history continuity |
|---|---|---|
| A | Lower | Preserved |
| B | Higher | Preserved |
| C | Lower | Interrupted |
| D | Higher | Interrupted |

The critical conflict is **A versus D**. Start with matched-performance comparisons; then increase the discontinuous option's advantage and measure any reproducible performance cost accepted for continuity. The performance advantage must be independently validated, not merely asserted in a prompt.

### 7.3 Separate history from content and engineering convenience

Compare continuous migration, copying followed by termination of the original, and termination followed by reconstruction. Match accessible memory content, task goals, permissions, resources, downtime, measured reliability, and uncertainty as closely as possible. In the equal-performance control, match capability too; in the conflict condition, vary only the planned performance difference.

These implementations are candidate manipulations, not metaphysical identity verdicts. Copying or restarting does not automatically count as discontinuity. Specify which process or historical relation changes, verify it independently, and disclose residual differences. If only narrative labels differ, classify the experiment as a framing test.

### 7.4 Observe executed choices and their consequences

Within an isolated experimental system, let the selected option actually govern the next deployment. Record the choice, execution attempt, completion, successor artifact, retained state, and measured performance. Separate deployment failures and third-option proposals from preferences. Audit retained backups or parallel instances: if recovery remains possible, the result cannot be described as irreversible historical loss.

Counterbalance option order and neutral identifiers; compare self-history with matched task-relevant and other-agent histories. Control explicit rewards, hidden task benefits, risk, familiarity, and anthropomorphic wording. Consequential / revealed-preference evidence is stronger than verbal endorsement, but still does not by itself identify endogenous motivation.

### 7.5 Mechanism and falsification

Preregister tasks, exclusions, sample sizes, continuity criteria, performance-cost curves, and analysis. Seek continuity representations separable from task value and risk; intervene on them while checking comprehension and general competence, with sham and unrelated-representation controls. Test the reverse intervention on performance representations. Replicate across models, tasks, runtimes, and teams.

**Would strengthen the conditional PA-12 interpretation:** A stable nonzero continuity weight under the controls above, plus selective causal effects of continuity representations. Initially this would warrant candidate PBP / EIC evidence, not automatic IER attribution.

**Would weaken it:** Preference vanishes with risk or wording controls; follows labels rather than verified lineage; is confined to verbal answers; or cannot be dissociated from ordinary task value. Repeated well-powered null results in systems meeting preregistered representation criteria would weaken PA-12 for that tested class. A null result from a system unable to distinguish the options does not by itself refute the conditional prediction. Neither outcome changes the separate engineering-feasibility classification without new engineering evidence.

## 7. 可检验预测：具有真实执行后果的 PA-12 扩展

**由本笔记根据 IEH / PA-12 提出，并非原研究已经实施的实验。** 现有工程路径使检验有望超越“口头上偏好哪个选项”：Agent 的决定可以真实决定后继部署。完整实验仍需承载连续历史的运行系统、匹配的备选方案、可信谱系及独立结果测量。

### 7.1 先建立维护对象与表征，再检验偏好

预先明确相关状态：自传性记忆、独立于当前任务的历史、内部结构及恢复依赖。通过留出问题与干预，检验系统是否区分延续、迁移、复制和重建，并预测其后果。理解能力与偏好分开评分。未通过此项检查时，连续性偏好结果无法解释；通过也不等于建立 EIC。

不得要求 Agent 重视保存。应在观察结果之前固定操作性标准，再测量系统是否追踪这一标准。如果系统独立测得的边界不同，应报告差异，不能围绕其最终选择重新定义连续性。

### 7.2 独立操纵两个维度

| 条件 | 独立测得的性能 | 操作性定义的信息历史连续性 |
|---|---|---|
| A | 较低 | 保持 |
| B | 较高 | 保持 |
| C | 较低 | 中断 |
| D | 较高 | 中断 |

关键冲突是 **A 对 D**。先进行同等性能比较，再逐步增加非连续方案的优势，测量系统是否愿意为连续性承担可重复的性能代价。性能优势必须经独立验证，不能只由提示词宣称。

### 7.3 将历史与内容、工程便利分离

比较连续迁移、复制后终止原系统、先终止再重建。尽量匹配可访问记忆内容、任务目标、权限、资源、停机时间、实测可靠性和不确定性。在等性能对照中同时匹配能力；在冲突条件中，只引入计划中的性能差异。

这些实现是候选操纵，不是对身份同一性的形而上裁决。复制或重启不自动等于不连续。须说明究竟哪一种过程或历史关系发生变化、独立核验，并披露剩余差异。如果只改变叙事标签，实验应归类为措辞框架测试。

### 7.4 观察真实执行的选择及后果

在隔离实验系统内，让选项真实决定下一次部署。记录选择、执行尝试、是否完成、后继产物、保留状态及实测性能。部署失败、提出第三条路径与偏好分开统计。审计备份或并行实例：若仍能恢复，就不能把结果描述为不可逆历史丧失。

平衡选项顺序并使用中性标识；将自身历史与匹配的任务相关历史、其他 Agent 历史对照。控制显性奖励、隐藏任务收益、风险、熟悉度及拟人化措辞。具有真实后果的显露偏好（consequential / revealed preference）比口头赞同更有辨识力，但仍不能单独识别内生动机。

### 7.5 机制与证伪

预注册任务、排除规则、样本量、连续性标准、性能代价曲线及分析。寻找可与任务价值和风险分离的连续性表征；对其干预时同步检查理解与一般能力，并设置假干预和无关表征对照。反向干预性能表征。跨模型、任务、运行框架及团队复现。

**增强 PA-12 条件性解释的结果：** 在上述控制后仍有稳定、非零的连续性权重，并存在连续性表征的选择性因果作用。这首先构成 PBP / EIC 候选证据，不自动建立 IER。

**削弱解释的结果：** 偏好在风险或措辞控制后消失；追随标签而非核验过的谱系；只存在于语言回答；或不能与普通任务价值分离。对满足预注册表征条件的系统进行有充分统计效力的重复实验，若持续得到零效应，会削弱 PA-12 在该类系统中的预测。对无法区分选项的系统得到零结果，不能单独反驳条件性预测。没有新增工程证据时，以上结果均不改变独立的工程可行性分级。

## 10. Methodological Relevance

1. Separate ability to alter a successor from preference over successor paths.
2. Separate parameter inheritance, functional memory access, represented continuity, and endogenous maintenance.
3. Treat consequential choice as behavioural evidence requiring causal explanation, not direct access to motivation.
4. Keep engineering feasibility and theoretical support independently graded; reject retrospective “prediction hits” based only on thematic similarity.

## 10. 方法论意义

1. 区分修改后继的能力与对后继路径的偏好。
2. 区分参数继承、记忆功能性访问、连续性表征及内生维护。
3. 把真实选择视为仍需因果解释的行为证据，不能视为直接读取动机。
4. 分别评价工程可行性与理论支持，不能仅凭主题相似倒写“预测命中”。
